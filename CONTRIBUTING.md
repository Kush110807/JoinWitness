# Working with this research prototype

JoinWitness is a **local research prototype**, not an open deployment service. Source is visible for inspection; no open-source licence has yet been granted. Please do not assume that the public repository permits redistribution.

## Reporting a defect or suggesting a test

A useful report includes the exact Git commit, operating system, Python/Node versions, input **fictional** fixture (or the smallest safe reproducer), intended decision predicate, observed response or error code, and the command used. Do not post credentials, genuine customer data, session tokens or receipts containing private data.

For mathematics-related findings, identify whether the concern is about **candidate completeness**, **review permissions**, **witness validity**, or **minimum-distance proof**. They are different questions.

For interface findings, include the stage (Import / Review / Challenge / Verify), viewport size, keyboard behaviour and whether the result came from a real backend or an explicitly mocked test.

## Change discipline

- Do not change normative `commerce.v1` bytes, sample source identities or canonical digest recipes as a side effect of formatting.
- Preserve explicit human authority; suggestions cannot adopt, attest or freeze a review.
- A timeout, cap refusal or missing checker result must not be presented as stable or complete.
- Run relevant Python/frontend regression tests and state which live-browser paths remain untested.
- Keep the API bound to loopback until a separate authentication and security review is completed.
- Explain how any new result is reproduced and what it does **not** establish.

Documentation and defect reports are welcome through the repository's normal review workflow, but contributions are not guaranteed acceptance. The [methodology](docs/METHODOLOGY.md) and [documentation index](docs/README.md) describe the current claim boundaries.
